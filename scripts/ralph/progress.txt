## Codebase Patterns

- **Middleware key for onboarding slice**: Store registers it as `onboarding2` but the slice selectors use `state.onboarding`. Pre-existing inconsistency. For middleware tests, mount the reducer at `onboarding` key to match selectors. Do NOT try to fix this inconsistency in passing.
- **Middleware test setup**: Use `configureStore({ reducer: { sliceName: reducer }, middleware: (gDM) => gDM().concat(myMiddleware) })`. Test helpers `_resetState` / `_getState` exported from middleware for state inspection.
- **Pre-existing test failures**: 30 tests were failing before batch-4 work began (forgettingCurveService, settingsSlice, datasetValidation, HUD, antiFrustrationMiddleware, zoneReviewMiddleware, battle.integration, spacedListeningService). Do not try to fix these — they are known pre-existing issues.
- **Extending slices**: Export constants (like `TUTORIAL_SEQUENCE`) alongside the slice so both the middleware and tests can import them without circular deps.
- **Fake timer date gotcha**: `describe`-level `const` declarations run at module load time (BEFORE `beforeEach` installs fake timers). Never use `new Date(Date.now() ± offset)` at describe scope. Always use hardcoded absolute ISO strings: `'2020-01-01T00:00:00.000Z'` (past) and `'2030-01-01T00:00:00.000Z'` (future) relative to the fake "now" of `2026-02-09T00:00:00Z`.
- **Redux 5.x INIT action type**: Redux 5.x generates `@@redux/INIT<random-suffix>`. Use `action.type.startsWith('@@redux/INIT')` in middleware, NOT `=== '@@redux/INIT'`. The existing worldTimeMiddleware has this bug but it's masked because its clock tests avoid setInterval.
- **Interval middleware test pattern**: For testing setInterval-based middleware with fake timers: (1) use `middleware: () => [myMiddleware]` (no `getDefaultMiddleware`) to avoid RTK timer interference; (2) trigger clock start via explicit `store.dispatch({ type: 'persist/REHYDRATE', payload: null })`; (3) use `vi.advanceTimersByTime(interval + 1)` (1ms over) to guarantee firing.
