## Codebase Patterns

- **Middleware trigger signal**: Use an existing Redux action as the intercept point rather than creating new actions. For quiz completion, `dailyGoals/updateDailyGoal` with `goalType === 'quizzesPassed'` is the reliable session-end signal (only fires on score > 0, never for abandoned sessions).
- **Module-level daily state**: All middleware use a `_daily = { date, ...counters }` pattern with `_maybeResetForNewDay()` checking UTC date. Always export `_resetDailyState(overrides)` and `_getDailyState()` for test isolation.
- **Dedup key**: Use `new Date().toISOString().slice(0, 16)` for 'YYYY-MM-DDTHH:MM' minute-granularity dedup keys.
- **Middleware registration**: Import in `src/store/store.js` and append to the `.concat(...)` chain after `dailyGoalsMiddleware` so it sees actions after the goals reducer has processed them.
- **Pre-existing test failures**: 7 test files (antiFrustrationMiddleware, zoneReviewMiddleware, battle.integration, settingsSlice, datasetValidation, forgettingCurveService, HUD) were already failing before this batch. Do NOT treat them as regressions.
- **Hook reminder**: The `READ-BEFORE-EDIT` hook fires on every edit to an existing file, even if already read. It's a reminder only — edits go through as long as the file was read earlier in the session.
