# Milestone v6.0: Combat & RPG

**Status:** SHIPPED 2026-02-13
**Phases:** 27.1, 28-30
**Total Plans:** 16

## Overview

v6.0 transforms the battle engine foundation (Phase 27) into a complete combat RPG system. Players master Arabic through root-based magic where trilateral roots become spells, manage equipment with Arabic affix vocabulary, and recruit 12 AI companions who teach Arabic through conversation and battle. The roadmap addressed the critical localStorage overflow blocker first, then built the three core systems in dependency order: magic (the educational core), equipment (enhances magic via affinity bonuses), and companions (interact with both systems).

## Phases

### Phase 27.1: IndexedDB Migration (INSERTED)

**Goal**: Prevent save data loss by migrating FSRS cards and battle history to IndexedDB before adding new equipment/companion/magic state.
**Depends on**: Phase 27 (battle engine foundation)
**Plans**: 2 plans

Plans:
- [x] 27.1-01-PLAN.md — IndexedDB adapter, quota service, and store migration to hybrid persistence
- [x] 27.1-02-PLAN.md — Tests for storage infrastructure and full regression verification

**Details:**
- Nested persistReducer for hybrid storage (IndexedDB for heavy data, localStorage for lightweight)
- Cached IndexedDB connection pattern to avoid repeated open() calls
- Versioned schema (DB_VERSION=1) with upgrade path for future stores

- Requirements: STOR-01, STOR-02, STOR-03

## Milestone Summary

**Decimal Phases:**
- Phase 27.1: IndexedDB Migration (inserted before Phase 28 for urgent localStorage overflow fix)

**Key Decisions:**
- Phase 27.1 inserted as blocker before Phase 28 — localStorage overflow requires IndexedDB migration FIRST
- Phase ordering: 27.1 (storage) → 28 (magic) → 29 (equipment) → 30 (companions) based on dependencies
- Magic before equipment: Root magic is educational core, equipment enhances magic via affinity bonuses
- Equipment before companions: Companions have equipment slots and give gifts requiring inventory
- Nested persistReducer for hybrid storage — preserves selector paths while using IndexedDB backend
- CompanionDialogueManager uses composition (not modification) of DialogueEngine
- Behavior tree over state machine for companion AI — priority-based decision making

**Issues Resolved:**
- localStorage overflow risk eliminated via IndexedDB migration (5 slices)
- Battle rewards wiring gap from Phase 27 closed via battleRewardsMiddleware (INTG-06)
- 149 new tests added bringing total to 1,023 (zero regressions)

**Issues Deferred:**
- COMP-07: 573 missing dialogue lines (content gap, not code)
- COMP-10: 12 missing companion sprite PNGs (art assets, not code)
- INTG-03: Bundle 661KB exceeds 500KB target (accumulated over 4 phases)
- ShopOverlay + CompanionUI not wired to GameLayout (~25 lines to fix)
- Equipment-magic affinity integration not yet connected
- No tests for Phase 27 battle code (~2.6K LOC) — carried from v5.0

**Technical Debt Incurred:**
- Bundle grew from 458KB to 661KB across 4 phases (approaching 700KB warning)
- BootScene loads ALL assets upfront (77 calls) — needs zone-based lazy loading
- BattleStateMachine COMPANION_ACTION state unused (in STATES enum but no handler)
- Array.from placeholder dialogue in battle/object comments (generic templates)
