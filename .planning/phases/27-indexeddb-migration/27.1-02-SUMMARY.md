## Decisions Made

**1. Real timers required for IndexedDB tests**
- Fake timers (set globally in setup.js) prevent IndexedDB async operations from completing
- Solution: `beforeEach(() => vi.useRealTimers())` in IndexedDB test suites
- Rationale: IndexedDB event loop requires real async environment for callbacks to fire

**2. Module reset pattern for middleware tests**
- Middleware uses module-scoped `hasCheckedQuota` session flag
- Tests need fresh middleware instance with reset flag
- Solution: `vi.resetModules()` + dynamic import in each test's beforeEach
- Rationale: Ensures each test gets predictable first-run behavior

**3. Hybrid persist integration tested via reducer shape**
- Full redux-persist integration is complex and depends on browser APIs
- Solution: Test that nested persistReducer doesn't change state shape (state.vocabulary.* paths preserved)
- Rationale: The critical invariant is selector path preservation, not redux-persist internals

## Issues Encountered

**1. fake-indexeddb/auto doesn't set window.indexedDB in jsdom**
- **Problem:** Adapter checks `window.indexedDB`, but fake-indexeddb only sets `global.indexedDB`
- **Solution:** Added `window.indexedDB = indexedDB` assignment in setup.js after importing fake-indexeddb/auto
- **Outcome:** Adapter works correctly in tests

**2. IndexedDB tests timeout with fake timers**
- **Problem:** All IndexedDB adapter tests hung indefinitely (timeout after 5-15 seconds)
- **Root cause:** Global fake timers in setup.js prevent IndexedDB async event loop from advancing
- **Solution:** Use `vi.useRealTimers()` in beforeEach for IndexedDB test suites
- **Outcome:** All 11 IndexedDB adapter tests pass in <20ms

**3. Middleware mocks not applied with vi.doMock()**
- **Problem:** `vi.doMock()` in beforeEach doesn't reliably mock already-imported modules
- **Solution:** Use `vi.mock()` at module level + dynamic imports in each test
- **Outcome:** Clean mock isolation, all 8 middleware tests pass
