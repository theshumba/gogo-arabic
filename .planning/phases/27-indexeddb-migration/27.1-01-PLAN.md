<objective>
Build the IndexedDB storage infrastructure and migrate the Redux store to hybrid persistence.

Purpose: Prevent localStorage overflow (5MB limit) before v6.0 adds equipment, companion, and magic slices that would push total state to 5-10MB. FSRS cards alone are 2-3MB for 1,220 words. This phase migrates heavy data (vocabulary + battle) to IndexedDB while keeping lightweight slices in localStorage.

Output: Working hybrid storage — vocabulary and battle slices persist to IndexedDB via custom adapter, all other slices persist to localStorage. Quota monitoring warns players at 80% usage. Existing save data auto-migrates.
</objective>

**1. `src/services/storage/indexedDBAdapter.js`** (~80 lines)
Custom redux-persist storage adapter implementing `getItem(key)`, `setItem(key, value)`, `removeItem(key)` — all returning Promises.

Key requirements:
- DB_NAME = `'gogo-arabic-idb'`, DB_VERSION = 1, STORE_NAME = `'redux-state'`
- Cache the db connection in module scope (`let dbInstance = null`) — do NOT open a new connection per operation (Pitfall 4 from research). Create a `getDB()` helper that returns cached instance or opens new one.
- `onupgradeneeded`: Create object store `'redux-state'` if not exists. Use versioned migration pattern from research (check `event.oldVersion < 1`) so future phases can add stores safely.
- `onblocked`: Log warning about another tab blocking upgrade.
- Error handling: Wrap all operations in try/catch. On IndexedDB unavailable (private browsing), throw descriptive error — do NOT silently fall back to localStorage (that would defeat the purpose).
- Do NOT close db after each transaction (connection reuse).
- Export default `indexedDBStorage` object with the 3 methods.

**2. `src/services/storage/storageQuota.js`** (~50 lines)
Two exported async functions:
- `checkStorageQuota()`: Uses `navigator.storage.estimate()` with feature detection. Returns `{ usage, quota, percentage, available, usageMB, quotaMB }`. If StorageManager unavailable, return `{ usage: 0, quota: 0, percentage: 0, available: false }`.
- `requestPersistentStorage()`: Calls `navigator.storage.persist()` with feature detection. Returns boolean. Log result.

**3. `src/services/storage/migrations.js`** (~60 lines)
Uses `createMigrate` from `redux-persist`.

Migration version 0 (localStorage-only) -> version 1 (IndexedDB):
- Read old localStorage keys: `persist:gogo-arabic` is the current root key. The vocabulary and battle slice data lives inside it as JSON strings.
- The migration function receives the state that redux-persist has already deserialized. The actual data movement happens automatically because redux-persist will now write to IndexedDB (new storage config) instead of localStorage.
- The migration just needs to return the state (data is the same, backend changes).
- After successful rehydration with new config, schedule cleanup of old localStorage key's vocabulary/battle fields (NOT the entire key — other slices still live there). Use a `setTimeout(() => { ... }, 5000)` to clean up old data from the root localStorage key AFTER the app has loaded. Read the old root key, parse it, delete the `vocabulary` and `battle` properties, write back.
- Wrap everything in try/catch. On any error, log and return state unchanged (graceful degradation per Pitfall 5).
- Export `migrate` (the createMigrate result) and `CURRENT_VERSION = 1`.

**4. `src/store/middleware/storageQuotaMiddleware.js`** (~40 lines)
Redux middleware that:
- On `persist/REHYDRATE` action: call `checkStorageQuota()`, then call `requestPersistentStorage()` (one-time on load).
- If quota percentage > 80: dispatch `showNotification({ message: 'Storage almost full. Consider clearing old battle history.', type: 'warning' })` using the existing `showNotification` action from uiSlice.
- Use a flag to only check once per session (not on every persist action — that would be too frequent and async middleware on every dispatch is expensive).
- Import `checkStorageQuota` from storageQuota.js and `showNotification` from uiSlice.
