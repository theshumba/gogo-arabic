## Decisions Made

**1. Nested persistReducer instead of split namespaces**
- **Rationale:** Preserves all existing selector paths (`state.vocabulary.fsrsCards`, `state.battle.battleHistory`). Split namespaces (`state.heavy.vocabulary.*`) would break 50K LOC of existing code. Nested persistReducer is transparent to all Redux consumers.

**2. Cached IndexedDB connection pattern**
- **Rationale:** Opening a new IndexedDB connection per operation is expensive (Pitfall 4 from research). Module-scope `dbInstance` cache with `getDB()` helper reduces overhead. Connection is NOT closed after transactions to enable reuse.

**3. Versioned schema with upgrade path**
- **Rationale:** DB_VERSION = 1 with `event.oldVersion < 1` check enables safe schema evolution. Future phases (28-30) may need additional IndexedDB stores (e.g., companion dialogue cache, spell combo history).

**4. 80% quota threshold for warnings**
- **Rationale:** Early warning before actual overflow. Gives players time to clear battle history or take other action. 80% chosen as standard "high water mark" for storage systems.

**5. 5-second cleanup delay**
- **Rationale:** Old localStorage vocabulary/battle data cleaned up AFTER successful rehydration. setTimeout ensures migration is complete before cleanup. Non-critical cleanup uses graceful error handling (won't block app if it fails).
