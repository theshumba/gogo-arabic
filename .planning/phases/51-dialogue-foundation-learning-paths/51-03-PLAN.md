    **Part A — Add path-choice dialogue trigger to InkDialogueEngine:**

    Add a static/class method or exported function `loadPathChoiceForAmira()` that:
    1. Loads `guide-amira-path.ink.json` specifically (not the general guide-amira.ink.json)
    2. The INK_FILES glob from Plan 51-01 already covers `src/data/ink/*.ink.json`, so `guide-amira-path.ink.json` is automatically included
    3. Add method `async loadPathChoice()` to InkDialogueEngine class:
       ```javascript
       async loadPathChoice() {
         try {
           const key = '../data/ink/guide-amira-path.ink.json';
           const loader = INK_FILES[key];
           if (!loader) { this._inkLoaded = false; return; }
           const mod = await loader();
           const { Story } = await import('inkjs');
           this._story = new Story(mod.default);
           this._bindExternalFunctions();
           this._inkLoaded = true;
           this._currentNpcId = 'guide-amira-path';
         } catch {
           this._inkLoaded = false;
         }
       }
       ```

    **Part B — Wire DialogueOverlay to display ink choices:**

    Read DialogueOverlay.jsx to understand its current structure. It renders dialogue text and response options. Add ink choice support:

    1. Add an `inkChoices` prop or state that, when present, renders ink choices as clickable dialogue options
    2. When `InkDialogueEngine.isInkLoaded` is true and `currentChoices().length > 0`, the overlay should display those choices as buttons/options
    3. When a player clicks an ink choice, call `inkEngine.chooseChoiceIndex(index)` then `inkEngine.continue()` to advance
    4. After the ink story reaches END (canContinue is false and no choices), call `syncStateOut()` and close the dialogue

    The exact implementation depends on how DialogueOverlay currently receives and renders data. Key integration points:
    - DialogueOverlay listens to an EventBus event (likely `EVENTS.DIALOGUE_START` or similar) — check the file
    - Add a new EventBus event `EVENTS.INK_DIALOGUE_START` or reuse the existing event with an `isInk: true` flag
    - When ink dialogue starts: syncStateIn, then loop continue+choices, render in overlay
    - When ink dialogue ends: syncStateOut, dispatch tutorial phase advancement

    **Part C — Trigger path-choice dialogue after first word learned:**

    In the game flow, after the first floating word is learned (ONBOARDING_FIRST_WORD_LEARNED flag set), the path choice should fire. Find where `tutorialPhase` transitions from `cinematic_intro` to `path_choice` (or `awaiting_mentor`). Instead of setting `tutorialPhase = 'path_choice'` (which triggers the old overlay), the flow should:
    1. Create an InkDialogueEngine instance
    2. Call `loadPathChoice()`
    3. Call `syncStateIn()`
    4. Emit the ink dialogue event to open DialogueOverlay with ink content
    5. After path is chosen (ink story ends), `syncStateOut()` sets ONBOARDING_PATH_CHOSEN flag
    6. Then set `tutorialPhase = 'awaiting_mentor'` (skipping 'path_choice' entirely)

But verify this is safe by checking ALL places that dispatch `setTutorialPhase('path_choice')`.

    ```jsx

    ```
