**Change 2: useFormatArabic.js — add defense-in-depth ambiguous check**

At the top of `src/hooks/useFormatArabic.js`, add an import for the merged vocabulary:

```js
import vocabulary from '../data/vocabularyAll.js';
```

This import is safe — `vocabularyAll.js` is a pure data module with no Redux imports, so no circular dependency risk.

Inside the `getTashkeelOpacity` useCallback (currently around line 42), add the ambiguous check AFTER the fsrsCard lookup but BEFORE any mastery-based calculation. The current code starts:

```js
  const getTashkeelOpacity = useCallback(
    (wordId) => {
      if (!wordId) return 1.0;
      const fsrsCard = fsrsCards[wordId];
      if (!fsrsCard || !fsrsCard.card) return 1.0;
      const { state, reps = 0, stability = 0 } = fsrsCard.card;
      // ... mastery levels ...
```

Change it to:

```js
  const getTashkeelOpacity = useCallback(
    (wordId) => {
      if (!wordId) return 1.0; // No wordId = show full tashkeel

      // CONT-07: Ambiguous words always retain full tashkeel regardless of mastery
      const wordMeta = vocabulary.find((w) => w.id === wordId);
      if (wordMeta?.ambiguous) return 1.0;

      const fsrsCard = fsrsCards[wordId];
      if (!fsrsCard || !fsrsCard.card) return 1.0; // No card = show full tashkeel
      const { state, reps = 0, stability = 0 } = fsrsCard.card;
      // ... rest of mastery levels unchanged ...
```

Note: The `vocabulary.find()` call in a useCallback is acceptable here because:
- `vocabulary` is a module-level constant (pure data, never re-allocated)
- The lookup only runs when a specific word's opacity is requested (not on every render)
- The performance impact is negligible for the ~6,000 word array with find()

Do NOT add `vocabulary` to the useCallback dependency array — it's a module-level constant, not React state. Adding it would not cause bugs but is unnecessary.
