## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/auth/magic-link/* | Untrusted email + token input crosses; zod validation at route entry; bcrypt-hashed token storage |
| email scanner → GET /verify | Pre-fetch scanners follow GETs; mitigation: GET renders confirmation page, POST consumes token |
| Mongo ↔ controller | tokenHash stored bcrypt-hashed; even DB read does not yield plaintext token |

## STRIDE Threat Register

| T-103-09 | Spoofing | Magic-link token replay | mitigate | consumedAt set BEFORE issuing JWT cookie; bcrypt-hashed token in DB |
| T-103-10 | Spoofing | Magic-link token brute force | mitigate | 32 random bytes = 2^256 space; per-IP authLimiter + per-email magicLinkEmailLimiter |
| T-103-11 | Information Disclosure | Account enumeration via request endpoint | mitigate | requestMagicLink always returns 200 with generic message |
| T-103-12 | Spoofing | Email scanner pre-fetch consumes token | mitigate | GET /verify renders form; POST /confirm consumes (Pitfall 2) |
