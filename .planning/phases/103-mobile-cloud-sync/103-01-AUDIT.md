The full chain `StatsPanel → SyncIndicator → sync.js → api.js → /api/v1/game/*`
is rooted at `StatsPanel`, which **no component renders**. The chain is therefore
mounted nowhere in the running app.

## Verdict

- **Client sync layer — DELETE.** `src/services/sync.js`, `src/components/HUD/SyncIndicator.jsx`,
  the `<SyncIndicator />` usage + import in `src/components/HUD/StatsPanel.jsx`, and the
  `saveGame`/`loadGame`/`resolveConflict` exports in `src/services/api.js` are unmounted dead
  code. This satisfies the user's pre-authorised "DELETE if SyncIndicator unmounted" condition.
  *(StatsPanel itself: confirm whether it has any other purpose before deleting the whole file —
  if its only content is the SyncIndicator, the file goes too; otherwise just remove the
  SyncIndicator import + render.)*

- **Server `/api/v1/game/*` routes — SUPERSEDE (deprecate now, delete with Plan 06/07).**
  These are real, tested routes from a prior cloud-save attempt, but no live client calls them.
  Phase 103 builds a new `/api/v1/cloudsave/*` namespace. Rather than delete tested server code
  mid-phase, mark `/api/v1/game/*` deprecated in Plan 01 and remove it (with its tests) when
  `/api/v1/cloudsave/*` lands in Plan 06/07, so the server is never left without save routes.

## Key link (per plan)

The new `/api/v1/cloudsave/*` **replaces** `/api/v1/game/*` (does not coexist) — the old routes
have no live consumer, so there is no integration to preserve.
