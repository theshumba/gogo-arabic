# Phase 87 — Difficulty Curve Engine

## Goal
Add a dynamic difficulty calibration system that adjusts quiz challenge difficulty based on player performance, detects fatigue, suggests breaks, and controls vocabulary introduction rate.

## Motivation
Research (Bjork's "desirable difficulty") shows optimal learning occurs at a 70-85% success rate. Too easy = boredom, too hard = frustration. This engine keeps players in the "zone of proximal development" by monitoring performance and adjusting in real time.

## Architecture

### 1. Difficulty Engine Service (`src/services/difficultyEngine.js`)
Pure function module (no side effects, no Redux imports). All functions are independently testable.

- `calculateDifficultyLevel(recentResults, windowSize)` — EMA of last N results, adjusts difficulty to maintain 70-85% success rate
- `getDistractorDifficulty(difficultyLevel)` — maps difficulty level to distractor closeness (0-1 scale)
- `calculateFatigueFactor(sessionMinutes, questionsAnswered)` — returns 0-1 multiplier (1 = fresh, 0.8 = fatigued)
- `shouldSuggestBreak(sessionMinutes, questionsAnswered, consecutiveErrors)` — break trigger logic
- `getRecommendedSessionLength(historicalSessions)` — average of past 7 sessions, clamped 10-45 min
- `getNewWordRate(recentMastery, currentLevel)` — vocabulary introduction rate based on mastery
- `rankQuizTypesForDifficulty(difficultyLevel, playerLevel, cefrLevel)` — ordered quiz types by appropriateness

### 2. Difficulty Slice (`src/store/slices/difficultySlice.js`)
Redux state for difficulty tracking.

State shape:
- `currentLevel` — one of DIFFICULTY_LEVELS
- `recentResults` — capped at 50 entries
- `sessionStart`, `questionsThisSession`, `consecutiveErrors`
- `breakSuggested`, `historicalSessions` — capped at 14
- `newWordsToday`, `maxNewWordsToday`

Reducers: `recordResult`, `startSession`, `endSession`, `acknowledgeBreak`, `adjustDifficulty`, `resetDailyWordCount`
Selectors: `selectDifficultyLevel`, `selectSessionStats`, `selectShouldBreak`, `selectNewWordBudget`, `selectRecentAccuracy`

### 3. Difficulty Middleware (`src/store/middleware/difficultyMiddleware.js`)
Listens for quiz/challenge completion actions. Records results, recalculates difficulty every 5 results, checks fatigue, adjusts word rate.

### 4. Break Suggestion Component (`src/components/UI/BreakSuggestion.jsx` + `.module.css`)
Non-blocking toast with study stats, gentle messaging, continue/break buttons. Re-appears after 10 min if dismissed.

### 5. Difficulty Dashboard Component (`src/components/UI/DifficultyDashboard.jsx` + `.module.css`)
Expandable panel showing current difficulty, accuracy trend (CSS sparkline), session duration, break timer, new words budget, motivational text.

### 6. Tests
- `src/services/__tests__/difficultyEngine.test.js` — all pure functions, edge cases, boundaries
- `src/store/slices/__tests__/difficultySlice.test.js` — all reducers, selectors
- `src/store/middleware/__tests__/difficultyMiddleware.test.js` — integration tests

## Constraints
- Create ONLY new files (no edits to existing files)
- CSS Modules, dark theme (#1a1a2e, #FFD700)
- Default exports for components (lazy loading)
- recentResults capped at 50, historicalSessions at 14
- Difficulty never jumps more than 1 level at a time
- Break suggestions are gentle, never punitive
- All engine functions are pure (no side effects)
