  <files>

    src/components/Achievements/AchievementToast.module.css
    src/components/Menu/SettingsMenu.jsx
    src/components/Menu/SettingsMenu.module.css
  </files>
  <action>
    For EACH component, follow this migration pattern:

    **Step 1: Read the component** — identify all `const styles = { ... }` blocks and any `style={styles.xxx}` usage.

    **Step 2: Create the `.module.css` file** — translate each JS style object key to a kebab-case CSS class:
    - JS: `overlay: { position: 'absolute', background: COLORS.overlay }` becomes
    - CSS: `.overlay { position: absolute; background: var(--color-overlay); }`
    - Replace ALL `COLORS.xxx` references with `var(--color-xxx)` (the CSS custom properties already exist in `src/styles/variables.css`)
    - Replace ALL `FONTS.xxx` references with `var(--font-xxx)`
    - For box-shadow values from theme.js pixelBtn/pixelPanel, inline the actual CSS values
    - camelCase CSS properties → kebab-case: `fontSize` → `font-size`, `backgroundColor` → `background-color`

    **Step 3: Update the JSX file:**
    - Remove `import { COLORS, FONTS, ... } from '../../styles/theme.js'` (if no longer needed)
    - Add `import styles from './ComponentName.module.css'`
    - Replace `style={styles.xxx}` with `className={styles.xxx}` (use kebab-case in CSS, camelCase import in JS: `styles.overlayContent` for `.overlay-content` — OR use bracket notation `styles['overlay-content']`)
    - **IMPORTANT:** For CSS Modules, the class name in the CSS file can use kebab-case, and the JS import uses bracket notation: `styles['overlay-content']`. Alternatively, use camelCase in CSS to allow dot notation in JS. **Use camelCase in CSS class names** for simpler JS access (e.g., `.overlayContent` not `.overlay-content`).
    - Remove the `const styles = { ... }` object entirely
    - If a style uses a dynamic JS value (e.g., computed from props or state), keep ONLY that specific inline style, not the whole object

    **Step 4: Handle edge cases:**
    - If theme.js `pixelBtn` or `pixelBtnGold` is used, create equivalent CSS classes that replicate the exact styles
    - If `fullScreenBg(url)` function is used, keep it as inline style (dynamic URL)
    - If Framer Motion `style` prop is used for animations, keep those specific animation styles inline
    - Preserve ALL existing className props — the CSS Module styles are ADDITIONAL or REPLACEMENT, not conflicting

    **Migration order (simplest first):**
    1. **NotificationToast** — small, straightforward toast styles
    2. **AchievementToast** — similar to NotificationToast
    3. **SignOverlay** — simple overlay with text display
    4. **SettingsMenu** — form controls with volume sliders

    **CRITICAL:** After EACH component migration, verify the component still renders correctly by checking that:
    - No `COLORS.` or `FONTS.` references remain in the JSX (unless dynamically computed)
    - No `const styles = {` block remains
    - The module.css file imports are correct
    - Build still succeeds: `npx vite build`
  </action>
