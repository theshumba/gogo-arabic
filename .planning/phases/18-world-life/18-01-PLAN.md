**NPC idle animation enhancement (LIFE-01) in `src/game/sprites/NPC.js`:**

The current NPC.js already has a 4-frame idle animation cycling at 3fps (frames 0-3 of the down-facing row). This looks like continuous walking-in-place. Replace with a more lifelike blink/shift-weight pattern using a timer:

1. Keep the existing `scene.anims.create()` for the idle animation key (`${id}-idle`) but change it to use only 2 frames: frame 0 (standing) and frame 1 (shifted weight). Set `frameRate: 4` and `repeat: 0` (play once, not looping).

2. Add a SECOND animation key `${id}-blink` using frames 0 and 2 (frame 2 = blink). Set `frameRate: 6` and `repeat: 0`.

3. Instead of `this.anims.play(animKey)` with repeat=-1, set up a timer-based cycle in the constructor:
   - Start on frame 0 (standing still)
   - Every 2000-4000ms (randomized per NPC to avoid sync), play either the idle (shift) or blink animation
   - Use `scene.time.addEvent({ delay: 2000 + Math.random() * 2000, loop: true, callback })`
   - In the callback, randomly choose between playing `${id}-idle` (shift weight) or `${id}-blink` animation
   - After the animation completes, NPC returns to frame 0 naturally (repeat: 0 handles this)

4. Store the timer event as `this.idleTimer` so it can be cleaned up in `destroy()`.

5. In `destroy()`, add: `if (this.idleTimer) this.idleTimer.remove();`

IMPORTANT: The spritesheet layout is 4 cols x 4 rows. Frames 0-3 are the down-facing row. Frame 0 = standing, frame 1 = step-left, frame 2 = step-mid, frame 3 = step-right. For a 2-frame "blink/shift", use frames 0 and 1 for shift-weight, and frames 0 and 2 for the blink feel. This gives visual variety without needing new assets.

**Smooth camera follow (LIFE-03) in `src/game/systems/PlayerController.js`:**

The camera already uses lerp values (0.08, 0.08) in WorldScene.js. Move camera setup INTO PlayerController for better encapsulation, and add a slight deadzone so the camera doesn't jitter on micro-movements:

1. Add a `setupCamera(mapPixelW, mapPixelH)` method to PlayerController:
   ```javascript
   setupCamera(mapPixelW, mapPixelH) {
     const cam = this.scene.cameras.main;
     cam.startFollow(this.player, true, 0.09, 0.09);
     cam.setBounds(0, 0, mapPixelW, mapPixelH);
     cam.setDeadzone(8, 8); // 8px deadzone prevents jitter on idle micro-movement
     cam.setBackgroundColor('#1A1A2E');
   }
   ```

2. The lerp values 0.09 provide smooth but responsive tracking (slightly higher than current 0.08 for a touch more responsiveness). The deadzone of 8px means the camera won't move for tiny sub-pixel position changes, preventing visual jitter.
