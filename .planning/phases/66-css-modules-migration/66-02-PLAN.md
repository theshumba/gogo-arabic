# Plan 66-02: CSS Modules Migration — Battle, Magic & Companions

## Context

Second wave of CSS Modules migration, targeting the three combat/RPG feature areas:
- **Battle** — 6 files, 84 inline occurrences (BattleResult 25, BattleOverlay 22, BossList 18, BattleArabicInput 10, BattleMenu 5, ComboCounter 4)
- **Magic** — 3 files, 46 inline occurrences (SpellMenu 26, MagicOverlay 15, RootDiscoveryToast 5)
- **Companions** — 5 files, 78 inline occurrences (CompanionUI 31, PartyPanel 23, CompanionCard 12, CompanionCommentBubble 7, RelationshipBar 5)

Total: 14 files, 208 inline style occurrences.

## Special Considerations

### Battle Components
- **BattleOverlay** has dynamic positioning for enemy sprites, damage numbers, and status effect icons. Keep `style={{ left, top }}` for pixel-positioned elements, move everything else to CSS Modules.
- **ComboCounter** has pulsing animation triggered by combo count changes. Convert to CSS `@keyframes` with a `.pulse` class toggled by state.
- **BattleResult** has conditional colors for victory/defeat. Use `.victory` and `.defeat` modifier classes.

### Magic Components
- **SpellMenu** renders a radial spell wheel with rotation transforms. Keep `style={{ transform: rotate(${angle}deg) }}` for dynamic rotation, move static styling to CSS Modules.
- **MagicOverlay** has Arabic calligraphy styling with RTL direction. Ensure `.arabicSpell { direction: rtl; font-family: 'Amiri', serif; }` in CSS Module.

### Companion Components
- **CompanionUI** has relationship-level color gradients (0-5 scale). Use CSS custom property: `style={{ '--rel-color': getRelColor(level) }}` with `.bar { background: var(--rel-color); }`.
- **PartyPanel** positions companion portraits in a formation layout. Keep positional `style={{ gridArea }}` for dynamic grid placement.

## Migration Approach

Same pattern as Plan 66-01:

1. Read each component, catalog all `style={{...}}`
2. Classify each as:
   - **Static** → move to .module.css (majority)
   - **Conditional** → use className toggling (`.active`/`.inactive`)
   - **Dynamic value** → use CSS custom property (`--var`) or keep minimal inline
3. Create .module.css file, replace inline styles with class references
4. Verify no visual changes
