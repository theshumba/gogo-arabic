<objective>
Cut over BootScene.preload() from per-PNG loading (969 individual `this.load.image`/`this.load.spritesheet` calls from Phase 38 Plan 02) to multi-atlas loading using the atlas files produced by Plan 02.

Purpose: This delivers the runtime half of PIPE-02. Per RESEARCH "BootScene-compatible extension" section, ONLY the `kenmi-shared` atlas loads at boot — per-zone atlases are deferred to Plan 06's ZoneLoader. This plan keeps BootScene tight (faster cold-start) while preserving zero behavioral change for sprite consumers (the frame-naming spike in Plan 01 confirmed atlas frame names === old catalog keys).

Output: BootScene that boots ~10x faster (multiatlas = ~12 HTTP requests instead of ~969) with no consumer-side changes anywhere in zones.js or scenes. The existing Phase 38 contract is preserved.

NOTE: This plan is parallel-safe with Plan 02 because Plan 02 only writes to `dist/` (build output) while this plan only edits `src/game/scenes/BootScene.js`. But Plan 03's *tests* require atlas files to exist — so the test must mock the Phaser loader OR the orchestrator must run `npm run pipe:pack-atlases` once before Plan 03 tests execute. Test strategy: mock the loader (no real network/file load) — see Task 2.
</objective>
