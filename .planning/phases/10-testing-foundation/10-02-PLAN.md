  <action>
    1. **Install dependencies:**
       ```bash
       cd server && npm install --save-dev vitest supertest mongodb-memory-server
       ```

    2. **Add test scripts to `server/package.json`:**
       ```json
       "scripts": {
         "test": "vitest",
         "test:run": "vitest run",
         "test:coverage": "vitest run --coverage"
       }
       ```

    3. **Create `server/vitest.config.js`:**
       ```javascript
       import { defineConfig } from 'vitest/config';

       export default defineConfig({
         test: {
           globals: true,
           environment: 'node',
           setupFiles: ['./test/setup.js'],
           include: ['src/**/*.{test,spec}.js'],
           poolOptions: {
             threads: {
               singleThread: true, // Prevent multiple MongoDB instances
             },
           },
           testTimeout: 30000, // MongoDB operations can be slow first time
         },
       });
       ```

    4. **Create `server/test/setup.js`:**
       - Import MongoMemoryServer from 'mongodb-memory-server'
       - Import mongoose
       - Set `process.env.JWT_SECRET = 'test-secret-key-for-testing-only-32chars!'` and `process.env.NODE_ENV = 'test'`
       - `beforeAll`: Create MongoMemoryServer instance, get URI, connect mongoose
       - `afterAll`: Disconnect mongoose, stop MongoMemoryServer
       - `afterEach`: Clear all collections (`for (const key in mongoose.connection.collections) await mongoose.connection.collections[key].deleteMany({})`)
       - Export nothing (runs via setupFiles)

    5. **Create `server/test/helpers.js`:**
       - Import jwt from 'jsonwebtoken'
       - Import User model (or relevant model) for creating test users
       - Export `createAuthToken(userId)` — generates a valid JWT with the test secret
       - Export `createTestUser(overrides = {})` — creates and saves a user in the test DB with default email/password/playerName, returns the user document + token
       - This helper allows route tests to authenticate without going through the register endpoint each time
  </action>

  <action>
    For each of the 6 route files, create test files using supertest against the Express app. Read each route file AND its corresponding controller to understand:
    - Endpoint URLs and HTTP methods
    - Request body schemas (Zod validation)
    - Authentication requirements (which routes need JWT)
    - Response formats (status codes, body shape)
    - Error cases (validation errors, not found, unauthorized)

    **Pattern for each test file:**
    ```javascript
    import { describe, it, expect, beforeEach } from 'vitest';
    import request from 'supertest';
    import app from '../../app.js';
    import { createTestUser, createAuthToken } from '../../../test/helpers.js';
    ```

    **Per-route specifics:**

    1. **auth.test.js** (POST /api/auth/register, POST /api/auth/login):
       - Register: valid data → 201 + token, duplicate email → 400, missing fields → 400
       - Login: valid credentials → 200 + token, wrong password → 401, unknown email → 401

    2. **user.test.js** (GET /api/user/profile, PUT /api/user/profile):
       - Get profile: authenticated → 200 + user data, no token → 401
       - Update profile: valid update → 200, invalid fields → 400

    3. **shop.test.js** (GET /api/shop/items, POST /api/shop/purchase):
       - List items: → 200 + items array
       - Purchase: valid item + enough dirhams → 200, insufficient funds → 400, invalid item → 404, no auth → 401

    4. **quest.test.js** (GET /api/quests, PUT /api/quests/:id/activate, PUT /api/quests/:id/complete):
       - List quests: → 200 + quests array
       - Activate: valid quest → 200, already active → 400
       - Complete: completed objectives → 200 + rewards, incomplete → 400

    5. **review.test.js** (GET /api/review/due, POST /api/review/submit):
       - Due cards: → 200 + cards array
       - Submit review: valid rating → 200 + updated card, invalid rating → 400

    6. **game.test.js** (GET /api/game/state, POST /api/game/sync):
       - Get state: authenticated → 200 + game state, no auth → 401
       - Sync: valid state → 200, version conflict → 409

    **Important notes:**
    - Import `app` from `../../app.js` (NOT server.js — server.js calls listen())
    - Use `createTestUser()` from helpers for authenticated routes
    - Set auth header: `.set('Authorization', \`Bearer \${token}\`)`
    - Each test is isolated because afterEach clears all collections
    - Read the actual controller code to understand exact response shapes and status codes
