# Plan 65-03: NPC Data Lazy Loading

## Context

`npc-data` chunk is **577 KB** (164 KB gzipped). It contains all 64 NPCs' complete data — metadata, dialogue trees, story arcs, and profession teaching — loaded eagerly on app start.

**Observation:** NPC *metadata* (name, zone, position, sprite info, vocabWords) is small and needed for world rendering. NPC *dialogue* (topics array with responses, conditions, effects) is the bulk of the data and only needed when the player talks to that NPC.

**NPC distribution:** 64 NPCs across 17 zones. Oasis Village alone has 18 NPCs.

## Implementation

### Step 1: Build-time split script

Create a Node.js script that splits `npcs.json` into:
- `npcs-meta.json` — NPC metadata only (id, name, zone, position, sprite, vocabWords, faction, schedule, etc.)
- `npcs-dialogue-{zone}.json` — Per-zone dialogue trees

Run this as a prebuild step or one-time generation (dialogue data changes rarely).

**Split logic:**
```javascript
// For each NPC, separate:
const meta = { id, name, zone, position, sprite, vocabWords, faction, schedule, personality, catchphrase };
const dialogue = { id, topics: [...] }; // the heavy part
```

**Estimated sizes:**
- `npcs-meta.json`: ~80-100 KB (all 64 NPCs without dialogue)
- Per-zone dialogue: ~20-40 KB each (17 zones)
- Total unchanged, just split across files

### Step 2: Create npcDialogueLoader.js

```javascript
// src/data/npcDialogueLoader.js
const dialogueCache = new Map(); // zone → Map<npcId, dialogueTopics>

export async function loadZoneDialogue(zoneName) {
  if (dialogueCache.has(zoneName)) return dialogueCache.get(zoneName);

  try {
    // Dynamic import — Vite splits each zone's dialogue into its own chunk
    const module = await import(`./npc-dialogue/${zoneName}.json`);
    const zoneDialogue = new Map();
    for (const npc of module.default) {
      zoneDialogue.set(npc.id, npc.topics);
    }
    dialogueCache.set(zoneName, zoneDialogue);
    return zoneDialogue;
  } catch {
    // Zone has no NPC dialogue file — return empty
    dialogueCache.set(zoneName, new Map());
    return dialogueCache.get(zoneName);
  }
}

export function getDialogueForNpc(npcId) {
  for (const zoneMap of dialogueCache.values()) {
    if (zoneMap.has(npcId)) return zoneMap.get(npcId);
  }
  return null; // Not loaded yet
}

export function preloadAdjacentZones(currentZone, zoneGraph) {
  const adjacent = zoneGraph[currentZone] || [];
  adjacent.forEach(zone => loadZoneDialogue(zone)); // fire-and-forget preload
}
```

### Step 3: Update npcsEnriched.js barrel

```javascript
// src/data/npcsEnriched.js — updated
import npcsMeta from './npcs-meta.json';
import { mergeNpcStoryArcs } from './npcStoryArcs.js';
import { mergeNpcProfessionTeaching } from './npcProfessionTeaching.js';
import { getDialogueForNpc, loadZoneDialogue } from './npcDialogueLoader.js';

// Enrich metadata with story arcs and profession teaching (small data)
const enrichedMeta = mergeNpcProfessionTeaching(mergeNpcStoryArcs(npcsMeta));

// Create a Proxy or getter that lazily resolves dialogue
const npcsData = enrichedMeta.map(npc => ({
  ...npc,
  get topics() {
    return getDialogueForNpc(npc.id) || npc._fallbackTopics || [];
  }
}));

export default npcsData;
export { loadZoneDialogue };
```

**Alternative (simpler):** Instead of Proxy, have DialogueOverlay call `await loadZoneDialogue(npc.zone)` before rendering dialogue. This is cleaner and makes the async boundary explicit.

### Step 4: Wire zone entry to dialogue preloading

In the WorldScene zone-change handler or zone transition middleware, add:

```javascript
import { loadZoneDialogue } from '../../data/npcDialogueLoader.js';

// On zone entry
loadZoneDialogue(newZoneName);
```

This preloads dialogue for the current zone so it's ready when the player talks to an NPC.

### Step 5: Update vite.config.js

```javascript
// NPC metadata (eagerly loaded, ~100KB)
if (id.includes('src/data/npcs-meta.json')) {
  return 'npc-meta';
}
// NPC dialogue files (lazy-loaded per zone)
if (id.includes('src/data/npc-dialogue/')) {
  return undefined; // Let Vite auto-split per dynamic import
}
// Keep story arcs and profession teaching in npc-data
if (id.includes('src/data/npcStoryArcs.js') ||
    id.includes('src/data/npcProfessionTeaching.js')) {
  return 'npc-data';
}
```

Remove the old `npcs.json` entry from manualChunks.

### Step 6: Generate the split files

Create a one-time build script `scripts/split-npc-data.js`:

```javascript
import fs from 'fs';
const npcs = JSON.parse(fs.readFileSync('src/data/npcs.json', 'utf-8'));

// Meta: everything except topics
const meta = npcs.map(({ topics, ...rest }) => rest);
fs.writeFileSync('src/data/npcs-meta.json', JSON.stringify(meta, null, 2));

// Dialogue: grouped by zone
const byZone = {};
for (const npc of npcs) {
  const zone = npc.zone || 'unknown';
  if (!byZone[zone]) byZone[zone] = [];
  if (npc.topics?.length) {
    byZone[zone].push({ id: npc.id, topics: npc.topics });
  }
}

fs.mkdirSync('src/data/npc-dialogue', { recursive: true });
for (const [zone, dialogue] of Object.entries(byZone)) {
  fs.writeFileSync(`src/data/npc-dialogue/${zone}.json`, JSON.stringify(dialogue, null, 2));
}
```

## Risk Mitigation

- **Dialogue not loaded when player talks to NPC:** Zone dialogue preloads on zone entry. If somehow not loaded, DialogueOverlay shows a brief loading state or waits.
- **Story arcs and profession teaching:** These are small (78KB + 2.3KB) and always needed — kept eagerly loaded.
- **Build script maintenance:** The split is a one-time operation. If npcs.json changes, re-run the script. Consider adding it to a prebuild npm script.
